# SiegeSense Step 4 — Coach Brain, Local AI, Voice & Match Report Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In Live Mode the coach talks to the player at the right moments.
- **Right after a death:** one specific tip about that death.
- **When a round ends:** one focus for the next round.
- **When the match ends:** a match report (top 3 problems, best moment, one drill).
- **Any time:** the player can ask a question by voice (push-to-talk) or text.

Tips are spoken aloud (offline Windows voices) and shown on a small in-game card. Nothing is shown or said mid-round. Everything is free and local.
- A rule-based coach always works.
- An optional local model (Ollama) rewrites tips naturally and answers questions, grounded in the session's facts.

**Architecture:**
- **Engine** gains a `coach/` package:
  - `LiveMechanics` runs the step 2 flick/habit analysers on input during Live Mode.
  - `CoachBrain` turns round summaries plus mechanics into prioritised `Tip`s with cooldowns, and merges repeats.
  - `MatchReport` builds the end-of-match report.
  - `LocalLLM` is an Ollama HTTP client with a grounding check and timeouts.
  - `SpeechToText` wraps faster-whisper (lazy model download) behind an interface with a fake.
- **LiveService** calls the coach at the death, round-end and match-end slots and pushes `tip` messages. New requests: `ask` (text) and `ask_audio` (WAV).
- **App:**
  - speaks tips with the Web Speech API
  - shows them in a Coach panel on the Live page
  - shows them on the overlay (now a general "coach card" + warm-up card)
  - registers a global push-to-talk shortcut (toggle), records the mic in the renderer and sends 16 kHz WAV to the engine
  - adds a Coach section to Settings

**Tech Stack:** Step 1–3 stack. New engine deps: `httpx` (Ollama), `faster-whisper` (speech-to-text, CPU int8; the model downloads on first use).

**Spec:** `docs/superpowers/specs/2026-11-01-siegesense-design.md` — build step 4 of §9: §4.8 CoachBrain, §4.9 LocalLLM, §4.10 Voice, the §6 overlay/Live coach behaviour, and the §4.8 match report.

## Global Constraints

- **Coach timing (§3, §4.8):** only at breaks — on death, at round end/prep, at match end, or when asked. Never mid-round.
  - The overlay shows a coach card only when a tip arrives, for 8 s, then fades.
  - **Never more than one spoken tip per break.**
- **Every tip carries its evidence (§4.8):** rule id, the numbers it is based on, and the round(s). Evidence shows in the Live coach panel.
- **LocalLLM (§4.9):**
  - Ollama at `http://127.0.0.1:11434`. Default model: the first installed model matching `qwen3:4b`, `llama3.2:3b`, `phi4-mini`, `gemma3:4b` (in that order), else any installed model.
  - Rewrites have a **4 s** timeout and answers a **10 s** timeout.
  - **Grounding:** if the output contains a number not present in the facts, the plain CoachBrain text is used instead.
  - Unavailable or slow → fall back silently. The coach light shows "Basic coach".
  - Calls happen only at breaks.
- **Voice (§4.10):**
  - Speech-to-text: faster-whisper `base.en`, CPU int8, offline after the one-time model download. The voice light shows the download state.
  - Text-to-speech: Web Speech API (Windows SAPI voices, offline).
  - Push-to-talk: a configurable global key, default **F9**. It toggles: the first press starts, the second press stops, and it auto-stops after **8 s**.
- **Fair play (§2):** tips talk about the player's own behaviour. The player's killer's name may appear (it was on their screen); nothing else about enemies.
- **Fully usable without Ollama and without the speech model.**

## Rulings carried in from the spec

- **TTS is the Web Speech API instead of Piper.** It's offline on Windows with zero install and a voice picker. Piper can be added later if the built-in voices aren't good enough.
- **Push-to-talk toggles instead of hold-to-talk.** Electron global shortcuts can't detect key release while the game has focus.
- **The speech model downloads on the user's PC** (Hugging Face is unreachable from the build environment). Speech-to-text is tested with a fake transcriber here.
- **Coach rule thresholds** below are first versions written from Siege fundamentals. They're constants in one file so they can be tuned after real matches.

## Coach rules (binding first version)

Each rule has an id, slot(s), priority (higher wins), a cooldown in rounds, a condition, and a template. "Recent" means the last 5 finished rounds.

| id | slot | prio | cooldown | condition | text (template) |
|---|---|---|---|---|---|
| `early_death` | death | 70 | 1 | died with `time_alive_s < 25` | "You died {t:.0f} seconds into the round. Slow your opening — clear one angle at a time and let utility go first." |
| `first_death` | death | 80 | 2 | this round `first_death` | "You took the first death. Don't take the opening fight alone — wait for a drone or a teammate before you swing." |
| `not_traded` | death | 60 | 2 | died, not traded, and this happened in ≥ 2 of recent rounds | "Your deaths aren't getting traded ({n} of the last {m}). Play closer to a teammate so they can refrag." |
| `overshoot_live` | death, round_end | 65 | 3 | ≥ 10 flicks this match, overshoot rate > 0.30 | "You're overshooting {pct}% of your flicks this match. Slow the end of your flick and stop on the head." |
| `moving_shots` | round_end | 50 | 3 | ≥ 15 shots this match, moving-shot rate > 0.50 | "{pct}% of your shots were fired while moving. Stop, then shoot — your first bullets will land." |
| `repeek` | round_end | 75 | 2 | a re-peek this round | "You re-peeked the same angle after a kill. After a kill, reposition — they know where you are." |
| `first_death_streak` | round_end | 85 | 3 | `first_death` in ≥ 3 of recent rounds | "You've died first in {n} of the last {m} rounds. Next round, let a teammate take first contact." |
| `crouch_spam` | round_end | 40 | 4 | ≥ 2 crouch-spam runs this round | "Crouch-spamming is throwing your aim off. Crouch once to change height, then hold." |
| `good_round` | round_end | 30 | 2 | round won and the player got first blood or ≥ 2 kills | "Good round — {what}. Keep that tempo." |

- **Delivery:**
  - On death, pick the highest-priority eligible `death` rule.
  - On round end, pick the highest-priority eligible `round_end` rule, but not one already delivered for this round's death.
- **Repeats:** if the chosen rule also fired in the previous round, append " (that's {k} rounds in a row)".
- **Report** (`MatchReport`):
  - `problems`: the top 3 rule ids by fire count, excluding `good_round`, each with a count and its latest text.
  - `best_moment`: the round with the most kills, tie-break first blood, as "Round N: K kills{, first blood}". `None` if there were no kills.
  - `drill`: mapped from the top problem:

    | Top problem | Drill |
    |---|---|
    | `overshoot_live` | warm-up drill `overshoot` |
    | `moving_shots` | `counter_strafe` |
    | `early_death`, `first_death`, `first_death_streak` | new `slow_opening` drill: "Play 3 rounds of Lone Wolf/T-Hunt where you clear every angle with your drone before entering." |
    | `not_traded` | new `trade_spacing` drill: "In your next 5 rounds, stay within one room of a teammate when you push." |
    | `repeek` | new `reposition` drill: "After every kill in your next match, move to a new angle before you peek again." |
    | none | warm-up drill `clean` |

## Review Focus

1. **Ollama is installed but slow, or it makes up numbers.** Expect the tip to fall back to the rule text within 4 s, and invented numbers to be rejected. → Task 3 `test_rewrite_timeout_falls_back`, `test_grounding_rejects_new_numbers`.
2. **No microphone, mic permission denied, or the speech model is not downloaded.** Expect a clear message in the coach panel and a voice light with a fix; text questions still work. → Task 4 `test_stt_unavailable_message`, Task 8 `mic denied shows message`.
3. **Several events in one break** (death, then round end 1 s later). Expect at most one spoken tip per break, and no duplicates of the same rule. → Task 2 `test_one_tip_per_break`, Task 5 `test_death_then_round_end_single_tip`.
4. **Tips during warm-up or with the coach off.** Expect no tips outside Live Mode, and `report_only` frequency to suppress death/round tips. → Task 5 `test_frequency_report_only`.
5. **The overlay is showing the warm-up card when a coach tip arrives** (warm-up and live at once are not allowed). Expect Live and Warm-up to be mutually exclusive with a clear error. → Task 5 `test_live_and_warmup_exclusive`.

### Task 3: LocalLLM (Ollama) with grounding

**Files:** `coach/llm.py`; deps `httpx>=0.27`. Test `test_llm.py` (a fake Ollama served by `aiohttp`-free `asyncio.start_server` minimal HTTP, or `httpx.MockTransport`).

**Interfaces:**
- `class LocalLLM(base_url="http://127.0.0.1:11434", model: str | None = None, transport=None)`:
  - `async status() -> LlmStatus(available: bool, model: str | None, reason: str | None)` (GET `/api/tags`, 1.5 s timeout, model chosen per Global Constraints)
  - `async rewrite(tip: Tip, facts: dict) -> str` (POST `/api/chat`, `stream:false`, 4 s timeout). The system prompt is a fixed coach persona: max 2 sentences, second person, use only the facts.
  - `async answer(question: str, facts: dict) -> str | None` (10 s timeout)
- `def grounded(text: str, facts: dict, base_text: str) -> bool`: every number in `text` (regex `\d+(\.\d+)?`) must appear in the JSON-serialised facts or in `base_text`.
- `def strip_thinking(text) -> str` removes `<think>…</think>` blocks (qwen3).

### Task 4: Speech-to-text and the question answerer

**Files:** `coach/stt.py`, `coach/answers.py`; dep `faster-whisper>=1.0`. Tests `test_stt.py`, `test_answers.py`.

**Interfaces:**
- `class SpeechToText(Protocol)`: `state() -> Literal["ready","not_downloaded","downloading","unavailable"]`; `async transcribe(wav: bytes) -> str`.
- `WhisperStt(model="base.en", download_root)`:
  - lazy load in a thread
  - `state` reflects whether the model files exist in `download_root`
  - the first `transcribe` triggers the download (state `downloading`)
  - errors → `SttUnavailable(reason)`
- `FakeStt(text)`.
- `def wav_to_float(wav: bytes) -> np.ndarray`: validates 16-bit PCM mono 16 kHz WAV and raises `ValueError` otherwise.
- `class Answerer(llm: LocalLLM | None)`: `async answer(question: str, facts: SessionFacts) -> Tip` (slot `answer`).
  - With the LLM: grounded answer or fallback.
  - Without it: keyword answers from facts:
    - "overshoot", "aim", "flick" → overshoot stats
    - "die", "death", "dying", "first" → deaths and first deaths with time alive
    - "trade" → traded counts
    - "peek" → re-peeks
    - "score", "round", "win" → rounds won/lost
    - else → "I can answer about your aim, deaths, trades, re-peeks and rounds this match."
- `SessionFacts` is a pydantic model built by LiveService (rounds summary + mechanics stats + recent tips).
- [ ] Tests:
  - `test_wav_to_float_valid` and `_rejects_stereo`
  - `test_stt_unavailable_message`
  - `test_keyword_answers` (each branch), `test_llm_answer_used_when_grounded`, `test_llm_answer_ungrounded_falls_back`

### Task 5: Coach in LiveService, protocol, status lights

**Files:** modify `live.py`, `server.py`, `status.py`, `services.py` (mutual exclusion); fixtures `tip.json`, `match_report` inside `match_summary.json`. Tests `test_live_coach.py`, `test_status.py`, `test_protocol.py`.

**Interfaces:**
- LiveService:
  - On a death event (after its clip): if frequency is not `report_only`, call `brain.on_death`, rewrite with the LLM if enabled, then push `tip`.
  - On `round_end`: `brain.on_round_end`, skipped when `key_moments` and priority < 70, or when `report_only`.
  - On stop: `build_report` → `MatchSummary.report: MatchReport`.
- One tip per break: a break is the window from a death until the next round start. At most one tip is pushed per break, whichever comes first, with death preferred.
- Requests:
  - `ask{text}` → `Tip`
  - `ask_audio{wav_b64}` → `{text, tip}`; `stt_unavailable` with a reason → error code `stt_unavailable`
  - `coach_status` → `{llm: LlmStatus, stt: state}`
  - `download_speech_model` → starts the download in the background
- Live and Warm-up are mutually exclusive: starting one while the other runs → `RequestError("busy", "Stop Warm-up first.")` (and vice versa).
- Status lights:
  - **coach:** ok "AI coach · {model}" when the LLM is available and enabled; ok "Rule coach" when `llm_enabled` is false; warn "Basic coach — AI not found" with fix "Install Ollama (ollama.com) and run: ollama pull qwen3:4b".
  - **voice:** off when `voice_enabled` is false; warn "Speech model not downloaded" with fix "Settings → Coach → Download speech model (≈140 MB)"; ok "Voice ready".
  - The LLM status is cached for 30 s.
